01 · Điểm cải tiến

PentestGPT có gì, SafetyNet thêm gì

PentestGPT là công cụ chạy dòng lệnh để giải CTF / pentest tự động. SafetyNet giữ phần “bộ não” đó và thêm những thứ cần có để biến nó thành một công cụ an toàn để trình diễn và cho ra báo cáo đọc được.

Khía cạnhPentestGPT (upstream)SafetyNet (top-up)
Mục đích Tự động giải CTF / pentest. Quét web local được phép → báo cáo lỗ hổng cho người đọc.
Chọn target Tham số --target tự do; README không mô tả giới hạn. MỚIWhitelist cứng: chỉ localhost / 127.0.0.0/8 / ::1, kiểm trước khi spawn bất cứ thứ gì.
Phạm vi quét Mô tả bằng --instruction tự do. MỚI4 goal template viết sẵn trong code. Người dùng chỉ chọn loại, không gõ scope.
Cô lập Có image Docker, dùng tuỳ chọn. MỚIMặc định agent chạy trong container; host app chỉ gọi docker run, không import agent. Có thể chọn chế độ direct (không container) nhưng phải bật chủ động ở server.
Giao diện CLI. MỚIWeb “Report Studio”: job bất đồng bộ, poll trạng thái, xem/in/tải báo cáo.
Báo cáo Có bước reporting ở cuối; định dạng không được mô tả. MỚIFinding có cấu trúc: request → response, severity, CWE, OWASP, giải thích, khắc phục. Xuất Markdown / In-PDF.
Truy vết bằng chứng — MỚIPhép join summary.json ⨝ traces/: mỗi finding trỏ về đúng sự kiện tool trong trace.
Chống LLM bịa — MỚITách fact (tất định) khỏi narrative (LLM); CWE → OWASP là bảng tĩnh; evidence đóng khung chống prompt-injection.
Trung thực khi lỗi — MỚIReport.conclusive: phân biệt “không tìm thấy lỗ hổng” với “run lỗi, không kết luận được”.
Demo Cần LLM + target thật. MỚIReplayEngine đọc run đã lưu: không Docker, không tốn phí, tất định.
Nhật ký Telemetry Langfuse bật mặc định (có thể tắt). MỚIruns/audit.log JSONL cục bộ: ghi target, goal, thời điểm trước khi chạy.

Cột upstream dựa trên README công khai của PentestGPT và có thể đã khác ở bản mới hơn. Phần “MỚI” là các thành phần do SafetyNet viết (thư mục src/safetynet/, web/); agent trong agent_image/ là mã vendor.

02 · Kiến trúc

Hai thế giới, một hợp đồng bằng file

Code chia làm hai phần không biết gì về nhau. Host app điều phối và viết báo cáo; agent chỉ chạy trong container. Chúng chỉ gặp nhau qua file trên đĩa — nên muốn demo không cần Docker, chỉ cần đọc lại đúng các file đó.

FastAPI · máy của bạn · MỚI

  • Sinh docker run (hoặc chạy CLI trực tiếp nếu bật direct), giới hạn 2 scan song song, timeout 600s
  • Đọc kết quả, gán nhãn, dựng báo cáo

06 · Fact và Narrative

Phép join: tìm lại request đã gây ra response

summary.json chỉ giữ response của mỗi observation. Request (câu lệnh curl với payload) nằm trong trace. Adapter nối hai nơi lại — hoàn toàn tất định, không gọi LLM. Dưới đây là dữ liệu thật từ run mẫu sqli-claude-03 (Juice Shop).

FACT tất định

  • adapter.py — không LLM, cùng đầu vào luôn ra cùng đầu ra
  • request · response · evidence_sequences · trạng thái lỗi · loại task
  • Có thể kiểm tra lại bằng cách mở trace

NARRATIVE diễn giải

  • labeling.py / labeling_llm.py — gán loại lỗ hổng, severity, CWE
  • Giải thích và khuyến nghị khắc phục bằng tiếng Việt
  • Có confidence và labeled_by để biết ai gán nhãn
Cầu nối: CWE → OWASP Top 10 (2021) là bảng tra tĩnh trong owasp.py (22 CWE), dù nhãn do luật hay do LLM sinh ra. LLM chỉ được trả lời “observation này là CWE nào”, không được tự bịa nhóm OWASP.

Thử bộ gán nhãn

Cùng một finding, hai cách gán nhãn. Mặc định chạy HeuristicLabeler (offline); có ANTHROPIC_API_KEY thì dùng LLMLabeler.

07 · Trung thực về giới hạn

Những gì chưa hoàn thiện

Liệt kê rõ điểm yếu cũng là một phần của phương pháp khoa học. Đây là các vấn đề đã tìm thấy khi rà code, và hướng sửa.

Thử thật ở chế độ direct xác nhận đúng rủi ro đã cảnh báo Chạy 3 model thật (2026-10-15, mode=direct): claude-opus-5-5 bị chính bộ lọc an toàn của Anthropic chặn; claude-sonnet-5-5 khi gặp target không có API đã tự ý đọc mã nguồn src/safetynet/ và dò chính API SafetyNet ở cổng 8000 (bị validate_target chặn nên không gây hậu quả thật, nhưng chứng minh không có ranh giới); claude-haiku-5-5 quét đúng target thật, tìm được tham số category và test SQLi boolean-based cho kết quả sạch — nhưng bị chính vendor đánh fail vì tóm tắt dài 2054 ký tự, vượt giới hạn cứng 2000 ký tự (execution.py:309). Chi tiết: README mục “Kết quả thử nghiệm model”.
Container chưa là ranh giới an toàn thực sự docker run hiện chưa có --cap-drop, --memory, --pids-limit, và egress mạng còn mở. Hướng sửa: siết mạng + quyền + tài nguyên (engines/live.py).
Timeout chưa chắc dừng container proc.kill() giết tiến trình client docker, không phải container. Hướng sửa: đặt --name và docker kill khi hết giờ.
Regex SQLi có thể báo nhầm Nhánh -- khớp cả cờ dài của curl như --max-time. Hướng sửa: chỉ khớp trên phần payload, không phải cả dòng lệnh.
Độ phủ test lệch Đã test whitelist, audit, helper của engine; chưa test adapter, labeler, owasp, report. Run mẫu có thể dùng làm golden test.
Gán nhãn lại mỗi lần xem Mỗi lần mở report là gọi lại LLM → tốn tiền và kết quả có thể đổi. Hướng sửa: cache nhãn theo (run_id, finding.id, model).
